# Station Max: безопасное управление блокировкой аналитики через hosts

## Область применения

Панель поддерживает два независимых способа управления `/system/etc/hosts`:

- **Стандартный режим** - старый механизм WEB-панели, когда внешняя служба защиты отсутствует.
- **adbguard v2** - опциональная интеграция с уже установленным на устройстве менеджером hosts. Панель управляет только флагом блокировки аналитики; OTA блокируется отдельным постоянным нижним слоем.

**PR не устанавливает adbguard, не меняет /odm, не делает root и не гарантирует защиту обновлений в период до запуска adbguard при загрузке.** Интеграция применима только к конфигурации с двумя профилями `/odm/etc/hosts-ota` и `/odm/etc/hosts-full` и службой `adbguard`. Другие реализации будут переведены в безопасный режим отказа, а не автоматически изменены.

## Автоматическое обнаружение

По умолчанию `YAPANEL_MAX_PRIVACY_BACKEND=auto`:

1. Если есть признаки внешнего менеджера (`adbguard`, его скрипт или профили), применяется строго проверяемый режим `adbguard-v2`.
2. Если нет внешней службы и hosts не смонтирован или подтверждено, что верхний одиночный mount принадлежит панели, работает прежний режим.
3. Неизвестные/чужие/многослойные mount не демонтируются: тумблер блокируется с описанием проблемы.

Можно принудительно указать `YAPANEL_MAX_PRIVACY_BACKEND=adbguard-v2`. Значение `panel` не обходит обнаруженную внешнюю защиту: при конфликте управление не разрешается. Наиболее безопасная установка - `auto`.

## Миграция при обновлении WEB-панели

| Исходное состояние | Что происходит | Примечание |
|---|---|---|
| Свежая установка, adbguard отсутствует | Сохраняется старый WEB-переключатель | Никаких команд установки root |
| Рабочий adbguard v2, ON | Панель показывает ON, OTA защищена | Требуется подтверждение профилей и правил |
| Рабочий adbguard v2, OFF | Панель показывает OFF, OTA защищена | Флаг не перезаписывается |
| Старый `boot_hook.sh` с bind panel-hosts + рабочий adbguard | При запросе статуса приватности удаляется *только* старая строка `bind` | Сохраняется `boot_hook.sh.pre-adbguard-v2.bak`; остальные команды остаются |
| Старый adbguard / конфликтующий bind | Режим отказа, без `umount` | Потребуется диагностика/ручная миграция |
| Чужой `/odm/etc/hosts` (root-кит), adbguard отсутствует | Режим отказа, без `umount` | Панель показывает, что аналитика уже блокируется внешним hosts; тумблер заблокирован |
| Остановленный/повреждённый adbguard | Режим отказа | Нет отката к panel-hosts, OTA не трогаем |
| `Удалить всё` | Внешние mount и флаг adbguard не трогаются | Собственный hosts снимается только при подтверждённом одиночном bind |

При обновлении код не удаляет `/data/quasar/webpanel/hosts`: старый файл может быть полезен для восстановления. Сам факт наличия файла не считается доказательством владения активным mount.

В стандартном режиме панель пишет в hosts оба семейства адресов: `127.0.0.1` и `::1`. Это закрывает обход через AAAA-запросы, который отдельно разбирали в базе Yandex Station Extended. В режиме adbguard оба семейства проверяются по содержимому активного hosts.

Очистка AppMetrica в стандартном режиме на Станции Макс ищет данные в `com.yandex.tv.services/no_backup/appmetrica` (там лежат `appmetrica_vital*.dat`), а старый путь `com.yandex.io.sdk/databases/appmetrica*` оставлен как fallback. Очистка выполняется только при подтверждённом panel-mount; в режиме adbguard и при конфликте она запрещена.

Миграция `boot_hook.sh` **идемпотентна**, с копией и проверкой `sh -n`. Если восстановить безопасность автоматически нельзя, панель сообщает об ошибке. Запрос `footprint(dry_run=True)` не меняет хук.

## Сценарии работы тумблера

При включении аналитики удаляется `/data/local/tmp/adbguard-analytics.disabled`; при выключении этот флаг создаётся. Все действия с bind mount выполняет **только внешний adbguard**.

Панель ожидает подтверждения состояния через `/proc/self/mountinfo`, содержимое активного hosts и `getprop init.svc.adbguard`. Переход считается успешным, если OTA-правила и оба семейства IP подтверждены.

- **OFF**: один слой `hosts-ota`, четыре OTA-домена заблокированы, аналитика не блокируется подготовленным hosts.
- **ON**: два слоя `hosts-ota` и `hosts-full`, четыре OTA-домена и девять аналитических доменов заблокированы.
- При неудаче выполняется попытка восстановить исходный флаг и подтвердить прежнее состояние. Неудачный откат не скрывается от пользователя.
- Очередь и файлы AppMetrica в режиме adbguard не удаляются.

Тумблер не гарантирует, что устройство действительно отправляет или не отправляет сетевые запросы: проверяется только активное содержимое hosts и монтирования.

## Ограничения

- Не поддерживается автоматическое обновление `adbguard v1` до `v2`. Обнаружен неизвестный mount - управление запрещено, потребуется сознательная миграция устройства.
- Обновления при самом старте устройства нужно блокировать также независимыми механизмами, если требуется защита до появления bind mount.
- Если на устройстве другое имя профилей/доменные правила, backend будет `unknown` до явной адаптации.
- Внешний `/odm/etc/hosts` панель не меняет. Если в нём есть только `127.0.0.1`, IPv6-покрытие зависит от внешнего менеджера; панель не может добавить туда `::1` без отдельного согласованного механизма.
- Перед релизом Windows-установщика нужно пересобрать `install_to_max.ps1` локальным `tools/build_installer.py`: встроенный tar обязан содержать `max_privacy.py`, иначе свежая установка через `install_to_max.bat` упадёт на `import max_privacy`. Файл `tools/` в git не входит; это шаг релизной сборки, а не CI.
- Android допускает распространение shared mounts: inode исходного `hosts-ota` при ON может отображать верхний `hosts-full`. Поэтому хеш исходного OTA-файла в режиме ON ненадёжен.
- Ранее на одном тестовом устройстве при переключении был разовый `Segmentation fault`, источник не определён. Нельзя заявлять, что этот PR устраняет сбой ядра/утилиты монтирования.

## Проверено на устройстве

- 2026-11-09, YNDX-0008, прошивка `5000000921`: `/proc/self/mountinfo` показывает единственный внешний mount с root `/etc/hosts`, `panel_owns_top=false`; `classify` возвращает `conflict`. Панель не снимает этот mount, тумблер блокируется. Проверка выполнена чтением, без переключения состояния.
